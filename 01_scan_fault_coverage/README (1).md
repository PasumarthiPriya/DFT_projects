# s27 D-Algorithm ATPG — Scan-Based Fault Simulation

A from-scratch **D-algorithm** ATPG (Automatic Test Pattern Generation) engine for the ISCAS-89 `s27` benchmark circuit, with the generated patterns applied to a **real gate-level, full-scan DUT** (not a second software model) to measure actual fault coverage.

## What this project does

1. **Generates test patterns** for all 52 single stuck-at faults (26 net locations × {stuck-at-0, stuck-at-1}) on `s27`, using a classical D-algorithm implemented in 5-valued logic (`0, 1, X, D, D'`).
2. **Applies every generated pattern to a real DUT** (`s27_scan_fi`) through a 3-bit full-scan chain, comparing the golden (fault-free) response against the faulty (fault-injected) response.
3. **Reports fault coverage** measured on the actual hardware model — not just claimed by the pattern generator — closing the loop between symbolic ATPG and gate-level verification.

This separation (pure ATPG search vs. scan-based fault simulation on real RTL) makes it easy to see whether a generated pattern *actually* detects the fault it was derived for once real sequencing (shift-in, capture, shift-out) is involved.

## Files

| File | Description |
|---|---|
| `tb_s27_datpg_scan.sv` | SystemVerilog testbench. Contains the D-algorithm ATPG engine (5-valued algebra, implication, D-frontier/J-frontier search with backtracking) plus the scan protocol driver that exercises the DUT. |
| `s27_scan_fi.v` | Verilog gate-level model of `s27` wired as a full-scan design, with a fault-injection "saboteur" on every one of the circuit's 26 internal net locations. |

## Circuit under test: ISCAS-89 `s27`

`s27` is a small sequential benchmark circuit with:
- **4 primary inputs**: `G0, G1, G2, G3`
- **1 primary output**: `G17`
- **3 D flip-flops** (present-state/next-state pairs): `G5/G10`, `G6/G11`, `G7/G13`
- **19 combinational gates** built from AND, OR, NAND, NOR, NOT, and buffer primitives

For full-scan test, the 3 flip-flops are wired into a single scan chain:

```
scan_in -> SFF0 (G5) -> SFF1 (G6) -> SFF2 (G7) -> scan_out
```

## How it works

### Phase 1 — D-algorithm test generation (pure symbolic search, no DUT)

For each of the 52 faults, the engine:
1. Initializes all nets to unknown (`X`) and sets the faulty net to `D` (stuck-at-0) or `D'` (stuck-at-1).
2. Runs **implication** (`imply_and_check`) to propagate known values and detect conflicts.
3. Searches the **D-frontier** for gates that can propagate the fault effect toward an output, selecting non-controlling side-input values.
4. Once the fault reaches a primary output/PPO, runs **line justification** via the **J-frontier** to resolve any remaining unknown inputs, backtracking on conflicts.
5. Records the resulting 7-bit test vector (`G0 G1 G2 G3 G5 G6 G7`) or marks the fault **redundant** if no pattern exists.

### Phase 2 — Scan-based fault simulation (real DUT)

For every pattern generated in Phase 1, the testbench drives the actual `s27_scan_fi` instance through the real scan protocol:

```
3 shift clocks (load G7,G6,G5) → apply PIs, strobe G17 → 1 capture clock → 3 shift clocks (unload G13,G11,G10)
```

Each pattern is run twice — once fault-free (golden) and once with the fault injected via the DUT's saboteur logic — and the two 4-bit responses (`G17, G10, G11, G13`) are compared. A mismatch means the fault is genuinely **detected** on hardware; a match despite having a "test pattern" would flag a **bad pattern**.

## Build & run

Requires [Icarus Verilog](http://iverilog.icarus.com/) (tested with `iverilog -g2012`, version 12.0):

```bash
iverilog -g2012 -o atpg.out tb_s27_datpg_scan.sv s27_scan_fi.v
vvp atpg.out
```

All 52 faults are testable, and every pattern generated by the D-algorithm is confirmed to detect its target fault when applied to the real scan-based DUT — **100% fault coverage**.

## Notes

- The saboteur in `s27_scan_fi.v` is implemented as a Verilog macro (`` `INJ ``) rather than a function, since a continuous assignment inside a function only re-evaluates on changes to the function's arguments — it would not respond to changes on the fault-control signals (`fault_en`, `fault_net`, `fault_val`) if they were read as plain module signals instead of arguments.
- The scan shift path reads the flip-flops' **raw** outputs (`q0, q1, q2`), so injecting a fault on `G5`/`G6`/`G7` corrupts only the combinational logic those signals feed — consistent with the stuck-at fault model — without corrupting scan shifting itself.
